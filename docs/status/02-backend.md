# Backend handoff

## Delivered local API

The FastAPI application is in `backend/src/job_hunter/api/main.py`; SQLAlchemy models and the database/session boundary are in `domain/models.py` and `adapters/database.py`. PostgreSQL 16 with pgvector is the only supported database. Alembic migrations `0001`–`0009` create the local schema, vector extension, tenant RLS policies, immutable confirmed profile revisions, ingestion provenance/category columns, bounded upload extraction fields and application packets. The local API uses the non-owner `jobhunter_app` role. It sets `app.user_id` transaction-locally from the fixed Alice/Casey development identity map before accessing private rows. Seed and migration commands use the owner URL.

The `/v1` API implements health and current user, editable profile and explicit immutable confirmation, preferences, filtered/ranked and paginated recommendations, job detail/review, application tracking, resume document create/read/revision-checked edit/duplicate/review, and PDF preview/reviewed export/download. `GET /recommendations` accepts `limit` (1–100), `offset`, and `q`; the response has `items`, `total`, `next_offset`, `degraded_mode`, and `ranking_status`. Job cards include source board, original URL, posted/fetched timestamps and the title-derived category provenance.

Application packets use revision-checked `PUT /v1/applications/{job_id}`. Send `resume_document_id` plus `expected_resume_revision` to create or reuse an export of that exact reviewed resume revision, or send an already-owned `resume_export_id`. The API snapshots the title and export revision; the linked PDF remains the same if the source resume is edited later. `cover_letter_text` stores user-authored text, up to 20,000 characters. Omitted packet fields preserve saved values; explicit null clears the field. GET and PUT responses include `resume_packet` with export/document IDs, title, revision and owned download URL, plus `cover_letter_text` and `packet_updated_at`. A composite foreign key prevents an application row from linking to another tenant's export, and export lookup/download also verifies ownership.

Local PDF upload accepts `POST /v1/uploads` with `{filename,content_type,size_bytes}`, followed by raw PDF bytes sent to the returned upload URL. It captures one immutable copy and SHA-256, enforces 10 MiB and 20 pages, and exposes extracted text via `GET /v1/uploads/{id}` as a review candidate. Encrypted, corrupt and textless/scanned-like PDFs report safe status codes; OCR is not implemented. Extracted text is not silently converted into structured profile facts. PDF rendering is isolated in `backend/src/job_hunter/preparation/rendering.py`. `layout` supports `font_size` (8–16 pt), `margin` (10–35 mm), `font_family` (`auto`, `serif`, `sans`, `mono`), `line_spacing` (1.0–1.8), and `page_size` (`A4`, `letter`). `auto` selects Times serif for classic and bundled Vera sans for modern; explicit mono uses Courier. Rendering applies these values to the actual PDF, including flowing multi-page content.

The ingestion component owns `backend/src/job_hunter/ingestion` and `import_jobs.py`; the ORM supports provider/board/external ID uniqueness and its deterministic title-only category is labelled with evidence (`title_keyword_v1` for the first import; since 17 October 2026 `role-family-v1`, from the shared classifier in `job_hunter/role_family.py` that the recommender also uses). Since the same day ingestion also classifies seniority levels from the title (or takes a level the source states) into `jobs.seniority`, `seniority_source` and `seniority_evidence` (migration `0013`, `job_hunter/seniority.py`); `python -m job_hunter.import_jobs --reclassify` (`make reclassify-jobs`) recomputes both from the stored titles. Its discovery/import paths are separate from normal API shared-job writes.

## Run and verify

From the project root, `docker compose up --build` starts PostgreSQL, applies migrations, seeds Alice/Casey and runs the API and web app. For the test suite against the running local DB:

```sh
docker compose run --rm --no-deps \
  -v "$PWD/backend/src:/app/src:ro" \
  -v "$PWD/backend/migrations:/app/migrations:ro" \
  -v "$PWD/backend/tests:/app/tests:ro" api \
  sh -c 'pip install pytest httpx -c requirements.lock && RUN_DB_INTEGRATION=1 pytest -q /app/tests'
```

Actual result on the shared Compose PostgreSQL database: **72 passed**. The suite includes end-to-end owned PDF upload/extraction and immutable-byte checks; packet creation from a reviewed resume, persistence, explicit clear, cover-letter edits, revision conflicts, foreign export denial, and proof that editing the original document leaves the attached PDF/title/revision unchanged; parser errors and limits; multi-page rendering in both templates, accented Latin names and bold markup; selected font-family resources, page dimensions, line-spacing pagination, and invalid layout validation; ingestion upsert behavior; API ownership, pagination/search; plus direct runtime-role SQL checks proving private rows are hidden without a user context and when switching from Alice to Casey. A separately created empty `jobhunter_packet_migration_test` database successfully applied migrations `0001`–`0009` and the synthetic seed. The local Python environment could not install packages because network access was blocked; verification therefore ran inside the Compose image. The test run emitted FastAPI `on_event` and Starlette/httpx deprecation warnings, no failures.

## Limits and follow-up

AI generation, semantic embeddings, usage reservations, task state/worker retry, profile fact extraction/confirmation UI, OCR, uploads deletion, Cognito, S3, Lambda/API Gateway and AWS RLS-role verification are not implemented. `/me` marks allowance accounting disabled and shows no usage value. The keyword ranker uses explicit location preferences as a hard filter, deterministic keyword/skill scoring and excludes reviewed jobs. PDF exports are created synchronously and stored on the local volume; automatic export deduplication and asynchronous task processing are deferred. Bundled Vera supports accented Latin text but not CJK glyphs. The live job adapter was tested separately by its owner; this backend handoff does not claim AWS source access, Bedrock, Cognito or cloud deployment verification.
