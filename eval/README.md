# System evaluation tooling

Scripts for the system evaluation in [SYSTEM-EVALUATION-PLAN.md](../docs/status/SYSTEM-EVALUATION-PLAN.md) (preliminary report, section 4.2). Everything here runs against **staging**. Announce load tests in the team chat first.

## Evaluation accounts (A3)

Six Cognito accounts, `jh-eval-01@example.com` to `jh-eval-06@example.com`:

- **Addresses:** `example.com` is a reserved domain, so no one receives mail. Invitation emails are suppressed.
- **Plan:** all are on the free plan, with 5 AI uses a month each.
- **Personas:** each holds one fictional profile, confirmed, with job preferences.

| Account | Persona | Preferred roles |
|---|---|---|
| jh-eval-01 | Data Engineer | Data Engineer |
| jh-eval-02 | Backend Software Engineer | Software Engineer, Backend Engineer |
| jh-eval-03 | Data Analyst | Data Analyst, Business Analyst |
| jh-eval-04 | Frontend Developer | Frontend Developer, Software Engineer |
| jh-eval-05 | Cloud and DevOps Engineer | DevOps Engineer, Cloud Engineer |
| jh-eval-06 | Business Analyst | Business Analyst, Product Analyst |

**Passwords** are generated by `seed_accounts.py` and stored only in `~/.job-hunter-eval/accounts.json` (mode 600) on the machine that created them. They are never committed or printed. Another operator can add their own accounts by running the script with a different number range, or reset a password with `admin-set-user-password`.

**Work modes are left empty.** Only the Lever source states a work mode (11 of 1,084 listings on 25 October 2026), and the eligibility rules exclude jobs with an unstated work mode whenever any mode is selected. With work modes set, each persona saw about 10 jobs; with them empty, 149–236 of the 309.

```sh
# Create any missing accounts and seed any unseeded ones (needs an operator SSO session and boto3).
AWS_PROFILE=<sso profile> python eval/seed_accounts.py
# Sign every account in and call /me.
python3 eval/cognito_tokens.py
```

**After the project,** delete the accounts. Their profile data stays in Aurora until the database is removed; use each account's "Delete profile data" first if it should go sooner.

```sh
for n in 01 02 03 04 05 06; do
  aws cognito-idp admin-delete-user --user-pool-id ap-southeast-1_rqE5iKEpf --username jh-eval-$n@example.com
done
```

## Tokens (A4)

`cognito_tokens.py` signs in through the same authorization-code + PKCE flow as the web app, by submitting the classic managed login form of our own user pool. Password sign-in (`USER_PASSWORD_AUTH`) is not used: its tokens lack the `jobhunter/use` scope the API requires.

- `login(email, password)` returns access, ID and refresh tokens.
- `refresh(refresh_token)` returns a new access token. Access tokens last 60 minutes and refresh tokens 1 day.

## Load tests (A4, B1, B3)

`locustfile.py` uses the evaluation accounts, refreshing tokens before they expire. It never calls the AI endpoints.

| User class | Used for | Behaviour |
|---|---|---|
| `BaselineUser` | B1 responsiveness | One user cycling evenly through `/me`, All jobs, For you, job detail, saved jobs, tracker, profile, profile bank and documents |
| `BrowsingUser` | B3 scalability | A weighted session: All jobs and For you ×3, job detail ×3, and `/me`, saved jobs, tracker, profile bank and Save/Pass ×1 each, with 1–3 s pauses |

Failures are labelled `429 throttled` (the deliberate gateway and Lambda caps), `5xx server error`, `401 auth` or `HTTP <code>`.

```sh
python -m venv .venv-eval && .venv-eval/bin/pip install -r eval/requirements.txt
# B1: per-endpoint baseline, one warm user.
.venv-eval/bin/locust -f eval/locustfile.py BaselineUser --headless -u 1 -r 1 -t 10m --csv eval/results/b1-baseline
# B3: step load 1 -> 10 -> 50 -> 100 users, 5 minutes each. Announce in the team chat first.
EVAL_STEPS=1,10,50,100 EVAL_STEP_SECONDS=300 .venv-eval/bin/locust -f eval/locustfile.py BrowsingUser \
  --headless --csv eval/results/b3-run1 --csv-full-history
```

A smoke test on 25 October 2026 (1 baseline user for 45 s, then 2 browsing users for 30 s) passed every endpoint, including the Save/Pass write, with no failures. From those few samples, All jobs and For you took about 1.3–1.5 s at the median and the other reads about 80–120 ms. That is indicative only, not a B1 result.
